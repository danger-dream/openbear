# 组网自动选路设计

## 0. 背景

在跨区域多节点组网场景中，中转（Relay）之间采用链路状态选路：每条线路持续测量延迟、抖动与丢包，按多跳最短路转发（见 `node/mesh/routing/README.md`）。早期设计中存在三个限制：

1. **成员不在选路图里**：普通成员同一时刻只挂载在一台中转（owner）下，发往它的流量必须先经过该中转。
2. **成员接入由人工排序**：「固定」模式只使用首个入口，「自动切换」仅在断线时切换，不按端到端路径成本择优。
3. **仅在已有线路上选路**：当某台区域中转与远端成员之间直连延迟远低于绕行其他洲际中转时，若未人工配置该连接，选路图上不存在对应边。

## 1. 设计原则

- **通用模型**：区域、连接限制、固定路径均为用户可配置的通用规则，不绑定特定网络拓扑。
- **复用现有选路引擎**：成员作为「不替他人转发的叶子节点（leaf）」进入同一张选路图，测量、公告、最短路、阻尼防抖、无环检查均复用 `routing` 包。
- **保持既有操作体验**：沿用草稿与应用、版本记录、「自动：原因 / 已改 / 恢复自动」、线路规则选择器、前置机、站点与公网中转，以及加入向导的测速推荐流程。
- **默认开箱可用**：单一区域、无连接限制和固定路径时，组网即可自动选择最快路径。
- **平滑混跑不断流**：新旧节点混合部署、迁移与自动调整期间不造成连接中断。

## 2. 概念模型

### 2.1 角色与接入

| 概念 | 说明 | 变化 |
|---|---|---|
| 中转（Relay） | 替其他节点转发流量；支持公网 / 站点模式及前置机 | 不变 |
| 成员（Member） | 仅承载自身流量，不作为中间跳替他人转发 | 进入选路图，作为叶子节点参与选路 |
| 上游中转（Upstreams） | 成员固定保持连接的一组中转（可多台） | 同时建立连接，无主备单点限制 |
| 可直连（Direct） | 成员级开关，默认开启 | 允许自动补充更优中转连接，或按需与同侧成员建立直连 |

成员发往任意目的地时，在「自身已建立连接（上游、自动连接、直连）+ 上游中转同步的全局拓扑图」上计算最短路，并从对应下一跳发出；成员永远不会出现在其他节点路径的中间跳。

### 2.2 连接限制（硬规则）

与线路规则并列展示于线路页顶部：线路规则定义「优先如何连接」，连接限制定义「允许与禁止哪些跨界连接」。

每条连接限制包含：

- **两侧选择器**：复用线路规则选择器，支持按区域（含反选）、标签或指定机器匹配（例如「区域为 CN」与「区域非 CN」）。
- **跨界约束条件**（勾选后须同时满足）：
  - 至少一端为中转：禁止普通成员之间直接跨界连接或打洞；
  - 仅允许指定传输协议：例如仅允许 TCP、TLS；
  - 必须经过指定节点：跨界连接至少一端位于指定白名单内；
  - 仅允许手动配置：自动建线不会在两侧之间生成跨界连接。
- **生效边界**：
  - 草稿校验逐条定位违规的接入、线路或直连，存在违规时禁止应用；
  - 自动建线、加入向导推荐与按需直连均自动跳过违规组合并给出原因；
  - 前置机自身的出口约束与分区连接限制同时生效。

### 2.3 自动建线

**轻量探测**：节点周期性对连接限制和前置机规则允许的候选对端执行轻量测速（不建立业务隧道）：

- 对开放 UDP 的公网中转复用反射请求计时；对仅开放 TCP/TLS 的节点测量 TCP 握手耗时；NAT 后节点单向发起测量即可。
- 默认每 5 分钟一轮（随机错峰），每目标采样 5 次计算中位数 RTT、抖动与丢包率，随状态上报主控。

**贪心择优与防抖**：

1. 主控基于当前拓扑计算所有节点对的最短路成本（`成本 = RTT + 2×抖动 + 1000×丢包率`）。
2. 逐一试算允许的候选连接：某节点对新成本低于原成本的 `85%` 且至少降低 `20ms` 才计为有效改善。
3. 每轮贪心选取总改善最大的候选连接加入图并重算，直至无有效改善或达到单节点自动连接配额（默认每节点最多 4 条）。
4. **防抖与抑制**：
   - 连续 3 轮探测均达标才建立连接；
   - 建立后改用真实链路测量评估，若实测未达标则标记为「实测不划算」，24 小时内不再重试；
   - 自动连接连续 1 小时无有效改善才自动拆除；
   - 用户手动删除某条自动连接后，7 天内抑制重建。
5. **自动版本下发**：
   - 仅在已应用配置上增减自动连接，不夹带未应用的草稿改动，并自动将新连接对齐合入当前草稿；
   - 两次自动版本间隔不少于 10 分钟，版本记录写明具体改善摘要（如「自动：新建 Relay-SG ↔ App-EU（让 App-AP → App-EU 从 271ms 降到 172ms 等 12 对）」）；
   - 关闭「自动调整线路」开关后仅展示测速建议，不下发自动变更。

### 2.4 固定路径

- **规则定义**：`从 A 到 B，经过 A → X → Y → B`。起点和终点是具体的服务器（中转，或经上游入图选路的成员），中间跳是按顺序相连的中转，最多 8 个；回程沿同一组中转反向走。终点的数据面不支持自建路线时（旧版节点），只有去程按路线走，回程走自动选路，起点也不对这条路线做端到端探测，只按链路状态判断。
- **同一对的多条路线**：同一对服务器最多 3 条，按顺序用第一条可用的；都不可用时走动态最短路。
- **故障回落与回切**：路线各段链路都在线、端到端探测有应答时，严格按指定跳数转发；任一段链路断开，或起点每秒一次的探测连续 3 秒没有应答，就换到下一条（没有下一条则走动态最短路）；恢复并持续稳定 2 分钟后切回。
- **转发实现**：源节点在端到端外层包的 identification 字段（这些包从不分片，该字段空闲）里标出所走路线的序号，路线上的中转按「源 + 目的 + 序号」选下一跳，包头零额外字节开销；中转只对来自路线上一跳的流量按路线转发，避免环路。

## 3. 数据面与滚动升级兼容

- **特性协商**：支持成员入图选路的节点声明 `mesh.routing.members`。
- **平滑迁移与混跑保护**：
  - 既有已应用的组网升级后默认保持原有接入模式与线路不变，旧组网的 `autoLinks.enabled` 默认关闭，不自动改写线上拓扑；
  - 仅当网格内全部活动中转与该 `upstreams` 成员自身均已支持 `mesh.routing.members` 时，主控才下发叶子选路配置（`leaf` / `memberLinks`）；任一中转仍处于旧版本时自动回退为兼容单入口故障切换格式，确保旧版中转不会收到扩展紧凑公告而拒收，实现零中断滚动升级。
  - 是否支持按各节点数据面**实际运行**的构建判断：节点程序已更新、数据面还没重启到新构建时，只去掉那个构建确实不认识的部分（1.2.0 的数据面全部去掉）；数据面已在新构建上运行的组网，之后再更新节点不会先推一版兼容配置。
