# Docker 子实例与主控管理

OpenBear 使用同一套源码与前端支持主控和受管子实例。只有进程环境明确设置 `OPENBEAR_INSTANCE_ROLE=managed` 才启用子实例流程；没有这个标识的现有安装保持主控行为。受管配置缺失时拒绝启动，不回退为主控。

## 边界

- 每个子实例仍是完整的单用户 OpenBear，不是共享数据库的多租户。
- 子实例不连接 Telegram。家人在独立认证网关使用账号密码登录，网关将请求转给对应子实例；账号、会话与撤销状态不依赖主控在线。聊天、记忆、定时、触发器、推荐、Skills、MCP 等仍属于该实例。
- 主控管理部署档案、配置、可用性和登录事件；不接收用户任务进度，不承担用户之间的传话或工作转交。
- 子实例自行完成任务和安装临时依赖。容器内安装不等于写入镜像，重建后可能丢失。
- 主控管理、网关管理、家人访问、子实例业务与事件上报是不同权限边界。应用凭证始终校验，选择 HTTPS 时正常验证证书；代码不按地址是否为私网限制 HTTP。主控与网关、实例之间怎样避免公网明文，见下文「网络与端口」。

## 同源码容器构建

在完整源码目录构建：

```sh
docker build -t openbear:managed .
```

本地镜像名不意味着其他服务器也能拉取该镜像。远程部署需要明确可取得的镜像引用，或者在授权的目标服务器按指定源码版本构建。不要假定存在某个官方已发布的镜像标签。

部署不要求主控本身容器化。主控可以继续使用原有 systemd 安装。

## 唯一持久卷

给子实例挂载一个独立的 `/workspace` 卷。该卷不只是用户文档目录，还必须保留：

- 数据库与会话、记忆、任务状态；
- 业务配置、网关业务凭证、管理与上报凭证（旧本地登录模式还包括密码哈希）；
- 解密历史材料、验证触发器等功能需要的持久密钥；
- 自定义 Skills、MCP 安装文件与私人文件；
- 自动事件的待上报队列。

不要把多个实例的可写卷指向同一目录，也不要挂载主控的数据库、凭证目录或 Docker socket。新建实例或修改数据目录时，程序拒绝系统目录和共用目录（如 `/root`、`/var/lib/docker`、`/etc`、`/home`）；本机部署还拒绝主控自己的项目目录、数据目录及它们的上级目录。已有实例只改其他设置时不重新检查数据目录。容器重建默认保留该卷；删除部署记录、停止容器、删除卷是不同操作。

普通 `docker restart` 保留容器可写层。删除并重建容器才会把镜像以外、卷以外的改动清除。常用软件可固化到基于同一 OpenBear 镜像的办公环境中。

跨版本升级前需要一致性备份。将镜像降回旧版本不保证旧代码能够读取新版本已迁移的数据库；不能自动恢复旧数据库覆盖新数据。

## 启动身份与凭证

受管启动使用这些环境参数：

| 参数 | 用途 |
| --- | --- |
| `OPENBEAR_INSTANCE_ROLE=managed` | 显式选择子实例模式 |
| `OPENBEAR_INSTANCE_ID` | 稳定实例身份 |
| `OPENBEAR_CHILD_AUTH=gateway` | 新部署使用网关认证，关闭子实例本地密码登录 |
| `OPENBEAR_GATEWAY_KEY` | 网关访问本实例业务 API 的独立凭证 |
| `OPENBEAR_MANAGEMENT_KEY` | 主控调用本实例管理 API 的独立凭证 |
| `OPENBEAR_REPORT_TOKEN` | 本实例向主控提交事件的受限凭证 |
| `OPENBEAR_CONTROLLER_URL` | 从子实例网络可达的主控上报基址 |
| `OPENBEAR_WORKSPACE` | 持久卷根目录，默认 `/workspace` |

旧卷的本地登录模式仍提供兼容恢复路径，但不会与网关模式同时启用。新部署不向子实例交付家人的登录密码；明确迁移旧卷时保留原业务数据。

业务、管理和健康上报凭证彼此独立，并且每个实例都不同。网关登录上报另用独立受限凭证。不要将主控自己的管理员凭证交给子实例。

环境变量注入并不构成对同权限 Bash 的强保密。程序避免向工具子进程传播管理环境变量以减少意外泄漏，但拥有实例内部文件和命令执行能力的用户仍可能接触本实例的私密状态。安全边界在于这些凭证无法管理主控或其他实例，也不能获得宿主机 Docker 控制权。

## 创建与部署会话

先在主控「实例」页面启用访问网关，再创建部署档案并启动部署会话。多个实例共用网关公共地址，以稳定实例 ID 区分路由。表单包括目标服务器、连接方式、持久目录、镜像及实际可达的访问地址。复制主控模型配置时，默认只复制默认模型所在的渠道（含 API Key），用户可再勾选更多渠道；已部署的实例不受影响。选中的连接凭证会作为受保护材料提供给本次配置的模型服务，以便模型执行部署；不要选择不允许接收这些材料的模型渠道。

模型负责根据实际服务器环境部署 Docker。实例 ID、目标、管理凭证、运行契约与报告归属由程序管理。会话来源 `deployment` 用于展示，不作为授权证明；复制或分支普通会话不应复制部署权限。

部署记录的结束分为两个层次：

1. 模型报告已执行的结果与证据。
2. 程序核验实例身份、鉴权管理接口、必要持久化与用户入口，再决定是否可用。

没有报告、会话中断或主控重启都不证明远程未执行任何操作。必须先核验已有资源，再决定如何继续，不自动重复部署或删除卷。

后续环境修复、容器升级和迁移通过关联的维护会话进行；普通记忆、模型、Skills、MCP 等业务配置可直接通过管理 API 调整。保留连接资料的目的之一是：子实例进程完全不可用时，仍能从服务器侧恢复，而不是只能依赖失效的子实例 API。

## 独立认证网关

Go 网关独立运行，只提供自己的登录页和认证/会话接口；登录后浏览器仍使用网关地址，由会话确定实例，页面、静态资源、API、文件和 WebSocket 都转发到该节点。网关不保存一套共用业务前端，也不是主控子进程。主控停止时，已有账号仍可登录，家人业务不依赖主控转发。网关密码只保存为密码哈希，路由、会话、撤销与待上报事件均保存在网关自己的状态目录。

源码构建（需要 Go 1.24 或兼容版本，竞态测试需要本机 C 工具链）：

```sh
python3 scripts/build_gateway.py --output gateway/bin
```

发行包提供 Linux amd64/arm64 网关二进制与校验清单，不要求使用者安装 Go。网关无需本地 `web/dist`；各节点使用自己镜像内成套的前后端，可以分别升级。需要兼容的是网关认证协议，而不是强制网关和全体节点具有同一应用版本。

网关只通过主控「实例」页面安装：选择运行位置（本机或已登记的服务器）、端口和公共访问地址后启用，主控会上传对应架构的二进制，生成管理密钥，安装并启动 `openbear-gateway.service`，再确认网关实际可连接。目标服务器需要 systemd，并以 root 或免密 sudo 用户执行。安装布局：

| 位置 | 内容 |
| --- | --- |
| `/usr/local/lib/openbear-gateway` | 网关程序 |
| `/etc/openbear-gateway/gateway.json` | 监听地址、公共地址和管理密钥，仅网关用户可读 |
| `/var/lib/openbear-gateway` | 账号、会话与待上报事件；由 systemd `StateDirectory=` 创建，每次启动时自动交给网关用户 |

网关以专用的 `openbear-gateway` 系统用户运行。登录入口端口对外开放；主控能访问运行位置的回环地址时（本机，或该服务器的节点在线且支持本机 HTTP 转发），管理接口另占一个只监听 `127.0.0.1` 的端口（从登录端口往后找空闲端口），登录端口上不再提供管理接口。只有 SSH 的服务器维持单端口：管理接口与登录入口共用端口，以管理密钥鉴权。再次保存网关设置会原地重装，保留账号和登录会话，并把旧的单端口安装按上述规则改为本机管理端口；更换运行位置或端口时，管理密钥会重新生成。网关放在哪台机器由用户决定，放在主控本机最安全。网关在管理接口的状态里报告自己程序的 sha256（`build`）。主控刷新状态时判断是否需要更新：网关的构建与主控自带的程序不一致、网关不报告构建（旧版本），或管理接口还能按上述规则移到本机端口。需要时「实例」页顶部和网关设置都显示“访问网关有新版本”和「更新网关」按钮；更新沿用当前运行位置、端口、访问地址和管理密钥重装，只重启网关，账号和登录会话保留。网关设置中的“自动更新”默认开启（旧安装同样视为开启）：主控启动后一拿到网关状态，发现需要更新就自动更新一次，成功或失败都通过实例通知渠道（Telegram）告知，失败时写明原因；同一目标构建失败后不自动重试，等主控下次启动或手动点「更新网关」。网关所在服务器离线或连不上时跳过，之后刷新状态时再试。关闭自动更新后只提示、不安装。安装和升级都不会修改或重启 `openbear.service`。

网络按实际部署选择：家人访问网关公共地址，网关访问子实例业务端点，主控访问网关与子实例各自管理端点，网关与子实例向主控上报。分别核验这些方向，不能把“地址已保存”当成“连接已成功”。主控会核对网关实际应用的 revision，并从公共入口探测真实子实例身份；保存、待同步、已同步、部署待验收是不同状态。

### 网络与端口

主控每次调用网关管理接口或实例管理接口都会带上对应密钥。为避免密钥走公网明文：

- 目标服务器有已连接、并且支持 `http.local` 的节点时，主控访问那台服务器上的网关管理接口和实例管理接口，都由节点在本机请求 `127.0.0.1:<端口>`，响应经主控与节点之间的加密通道送回。节点只访问回环地址、不跟随重定向，响应最大 2 MB、超时最长 60 秒；关闭了命令执行的节点不提供这项功能。本机实例和本机网关直接访问 `127.0.0.1`。
- 新建在本机或这类服务器上的实例，如果与网关在同一台服务器，端口只绑定 `127.0.0.1`，网关经 `127.0.0.1` 访问。
- 与网关不在同一台服务器时，两台服务器必须都是组网成员：端口绑定 `127.0.0.1` 和实例所在服务器的组网地址，网关经组网地址访问。不满足时保存和部署都会报错。组网网卡开机时可能比 Docker 晚起来，导致容器绑定端口失败，因此部署时会在该服务器上安装并启用 `openbear-instance-<容器名>.service`：开机后等组网地址出现再启动容器。
- 只有 SSH、没有可用节点的服务器维持原样：实例地址为“服务器地址 + 端口”，网关管理接口与登录端口共用。此时是否加密取决于用户自己的网络（HTTPS、可信隧道或防火墙）。手动填写了实例地址的实例也按填写的地址访问。

此前部署的实例保持原来的绑定，直到执行实例的网络迁移维护（实例详情「更多」→「迁移网络」，即 `POST /api/instances/{id}/migrate-network`）。需要迁移的实例会在「运行环境」中提示；暂时迁移不了时（节点版本太旧、不在线或关闭了命令执行，或网关在另一台服务器而两台不都在组网中），只显示原因，不提供迁移。迁移时：按上述规则计算新地址并记入实例记录，需要时安装开机启动单元，再重写 `compose.json` 并重建容器（数据目录不动），最后把新地址同步给网关。中途失败可以重新执行；手动填写了实例地址、或目标服务器没有可用节点的实例不迁移。网关本身通过「更新网关」（或自动更新）改为本机管理端口。

### 密钥更换

网关设置中的“更换密钥”会重新生成网关管理密钥（重装网关），以及每个实例的业务密钥和管理密钥；单个实例也可以单独更换（`POST /api/instances/{id}/rotate-keys`）。新密钥先保存在主控，再用子实例的离线维护命令（`set-auth`、`rotate-identity`）写入停止中的数据卷并重建容器，最后下发给网关。业务密钥变化会让该实例的全部登录会话失效，使用者需要重新登录。当时连不上的实例继续用旧密钥工作，主控在后台逐步延长间隔（最长 10 分钟）重试，恢复后自动完成更换并同步网关。

登录限制按客户端真实 IP 计算。网关默认只信任本机代理：直接访问时使用连接地址；连接来自本机（回环地址）时视为可信代理，并依次读取 `CF-Connecting-IP`、`True-Client-IP`、`X-Real-IP`、`X-Forwarded-For`、`Forwarded`；连接来自 Cloudflare 边缘节点时只读取由 Cloudflare 覆盖的 `CF-Connecting-IP`。内网里的其他机器带着转发头访问时不会被采信，网关设置会显示“发现未信任的代理”，确认是自己的反向代理后点“信任这个代理”即加入信任列表。也可以在网关设置中手动填写代理的 IP 或网段；留空则只信任本机和 Cloudflare。从旧版本升级时，主控会把旧网关最近报告的内网代理自动加入信任列表，原有内网反代部署不受影响。代理必须覆盖或清理这些请求头，不要直接透传客户端提供的值。页面显示的是网关实际确认后的识别结果。

共享入口也意味着共享浏览器 origin：受信任节点提供的前端脚本和通知 Worker 属于同一网站权限范围。该模式适合受同一管理方信任的节点，不把它当作相互恶意节点的浏览器安全隔离；需要这种隔离时，应另行规划独立 origin，而不是仅换一个端口或路径后宣称数据完全隔离。

同一浏览器同时只登录一个家人账号，换人先退出。业务请求同时校验登录 Cookie 和页面绑定值；旧标签页遇到新登录会停止请求，不自动改绑账号或重发草稿。退出、改密、撤销会话、停用实例均会撤销相应会话并中断连接。附件、图片、下载与 WebSocket 也执行此校验。

启用浏览器推送时，子实例还需能访问网关公共地址的会话状态端点；每次实际投递前验证原登录仍有效，网关不可达时暂停投递并重试，不依赖主控在线。通知携带真实实例标识，换人后的旧通知不能静默进入另一个账号。浏览器是否提供推送能力由其安全上下文和平台支持决定，不作为基本登录条件。

外部 Webhook 使用 `/i/{instanceId}/webhook/...` 专用路径，继续执行子实例原有 Webhook 鉴权；实例 ID 不是访问凭证。网关不会将浏览器 Cookie 或主控管理凭证传给子实例。归档记录不等于删除容器或卷；路由停用未获得网关确认时不宣称撤销已生效。

## 自动事件与状态

子实例程序自动上报心跳和运行健康变化，网关上报可归属实例的登录成功/失败事件，不注册给模型使用的通知工具。登录失败与成功是否通知，由主控中的配置决定。事件时间取主控接收时间与网关上报时间中较早的一个，网关时钟偏快也不会记成未来时间。Telegram 通知按实例限频：每个实例 10 分钟内最多 5 条，超出的不发送，下一个时段的第一条通知会注明期间未发送的条数。

实例和网关上报的健康状态、问题列表、版本等文本在写库和交给模型工具前截断（单项 200 字符、问题最多 20 条）；实例管理接口返回的 JSON 限制嵌套深度，异常响应按失败处理，不会让操作停在“进行中”。

事件不包含密码、Cookie 或管理 KEY。上报 TOKEN 只能提交所属实例的允许事件，不能执行主控管理操作。主控短暂不可达时保存事件、重试并去重，不阻塞登录或聊天。

“失联”“已确认故障”“部署待核验”是不同状态。后台周期探测有超时与退避，保留管理方向和网关方向的结果；一次网络超时不能被当作容器已经停止，也不能自动触发重建。状态变化和恢复各通知一次，不重复刷屏。延迟登录上报不会刷新健康心跳；心跳不逐条无限写入审计，历史事件可按类型分页，去重与终态通知记录有保留上限。主控启动恢复在后台补验收，不阻塞启动、不自动重复部署。

## 隔离联调

源码中的 `tests/gateway_stack_smoke.py` 可用已编译网关与节点前端产物启动一次性 loopback 主控服务与两个 Python 子实例，验证真实跨进程链路；不操作现有服务、容器或账号：

```sh
python tests/gateway_stack_smoke.py --gateway gateway/bin/openbear-gateway-linux-amd64 --web-root web/dist
```

可选 `--chrome /path/to/chrome` 验证真实双标签页换人和窄屏界面，使用临时浏览器资料目录；这不等于手机真机验收。

## 功能与资源

容器仍以 root 运行，进程数上限 4096；内存上限可在新建实例时按实例设置（至少 256 MB），默认不限。同仓镜像共享有助于复用只读文件和维护流程，但每个运行中的实例仍有自己的进程、数据和内存消耗。浏览器与办公转换等重型组件应根据使用需要配置；不能把 Docker 当作自动消除多实例内存开销的机制。
